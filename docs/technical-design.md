# 自然地理可视化技术设计

## 架构与数据流

Vite、React 和 TypeScript 构建静态页面。应用以 UTC 毫秒时间戳作为当前时刻，以经纬度和 IANA 时区描述观测点。地图、曲线和节气都从此状态派生。更换地点只更新观测点与时区，切换视图只更新渲染模式。日内数据按当前日期、地点和时区复用，年度数据按当前年份、地点和时区复用。

- **天文层**接收 UTC 时刻，生成地固太阳单位向量、太阳直射点和晨昏线几何。高度角是地表单位法向量与太阳向量点积的反正弦。点积为零的平面与球面相交形成晨昏线。沿时间的点积变化为正时属于晨线，为负时属于昏线。
- **地固坐标**用 Astronomy Engine 的太阳视位置、日期赤道坐标转换和格林尼治视恒星时求得。由太阳向量还原赤道坐标时使用该向量的历元，地球自转角用地面观测的接收时刻。经度东向为正，跨日界线归一到 −180° 至 +180° 的左闭右开范围。
- **高度角曲线**每五分钟为日内曲线采样，游标按实际选中时刻单独计算。全年曲线对当地每个存在的公历日期求太阳时角为零的上中天时刻。对无有效上中天的日期保留缺口。精确极点采用用户提供的经度定义参考子午线。
- **昼长**和晨昏线共用太阳中心的 0° 几何地平线。以当地日历日的首个和次日首个 UTC 时刻为边界复用日内高度样本。细化局部极值后对过零点二分求解，避免把两次采样之间的短暂白昼或夜晚误判为极夜或极昼。以真实经过的时长分别累计昼夜，支持跨午夜的分段和夏令时造成的长短日。缩短的日历日若全亮或全暗，会额外检查以当天为中心的 24 小时区间。
- **全年昼长**在 Web Worker 中用同一算法计算当前地点与时区的 365 或 366 个当地日期，以经纬度、年份和时区为键缓存结果。日期缺失时保留缺口，连续同类极区日合并为区间。跨年区间延伸到真实的起止日期，色带按所示年份裁剪。点击图上的日期复用太阳上中天时刻，若该日无上中天则用当地日的时间中点。
- **两地对比**复用同一个全局 UTC 时间戳和两套各自时区的昼长数据。A 点提供图表年份、节气标注日期及日期跳转时刻。B 点全年序列按相同公历月日对齐，B 点面板则按共享时刻在自身时区换算当地日期。两地点位各自计算并缓存，相同经纬度和时区复用 A 点结果。2D 与 3D 渲染共用两地点位和配色。
- **全球极昼与极夜范围**使用当前太阳赤纬的快照，假定赤纬在一次自转内恒定。两个极区的边界绝对纬度为 90° 减赤纬绝对值，太阳直射点所在半球的对应极区为极昼。2D 沿纬线填色，3D 在球面着色器中比较表面法向的北向分量。两种视图共用边界、半球和配色。赤纬绝对值小于 0.005° 时，极区范围缩至图例精度以内。
- **节气**由 SearchSunLongitude 按黄经每增加 15° 求交节时刻。先按 UTC 年计算并缓存，再按观测点当地年份筛选，提供当前和下一节气，包括一月初和年末相邻年份的节气。界面时间轴按真实日期定位。
- **地球公转**按同一 UTC 时刻取太阳视黄经、日地距离和真黄赤交角。公转图以太阳为中心，用太阳视黄经的反方向近似地球在黄道面内的位置。Canvas 对轨道、地轴和轨道面法线使用同一个斜视投影，以数值标注真实倾角，并放大太阳和地球符号。二分二至标记使用节气模块的同一批交节时刻。
- **渲染层**使用 Three.js 绘制球体，3D 着色器用共享太阳向量计算昼夜边界。2D 在 Canvas 上用经纬度采样着色，D3 裁剪跨 ±180° 的晨昏线。两种视图复用 Natural Earth 1:110m 陆地轮廓、海岸线和经纬格网。WebGL 2 初始化失败或上下文丢失时保留当前观测状态并切换到 2D。
- **时区层**用 @photostructure/tz-lookup 离线匹配坐标，允许手动修正。Temporal 根据浏览器的 IANA 时区规则处理夏令时和跨年。日内轴以真实经过的分钟数计算。手输不存在的本地时钟时刻会给出提示，重复时刻用 UTC 偏移消歧。海域使用数据返回的固定偏移。未来时区规则依赖浏览器的时区数据更新。
- **全年播放**用局部公历日期和固定起始钟表时刻计算下一次共享 UTC 时间戳，每次定时器回调推进一天。调速与暂停保留日期游标。夏令时跳时优先使用向后顺延的时刻，顺延跨出目标日期时尝试该日较早的时刻，整日缺失时跳到下一个存在的日期。日期轴、曲线或节气的手动操作暂停播放并定位到所选时刻。
- **全屏演示**复用当前时刻、播放控制器和地图、轨道、昼长组件。通过 Fullscreen API 进入浏览器全屏，接口不可用时用固定视口布局。CSS 根据宽高重排面板，Canvas 根据实测尺寸压缩图表的标签和留白。退出时恢复页面滚动位置和入口焦点。
- **使用引导**复用带焦点约束的原生对话框，按页面标记定位高亮区域，并随窗口和目标元素尺寸变化更新。日照地理首次访问展示八步引导，浏览器本地保存完成或跳过状态。公转及两地临时展示根据当前步骤派生。季节对比页在三张地图数据就绪后可从页首打开四步引导，打开时暂停月份播放，退出时保留所选月份、位置和气压层。关闭引导会恢复滚动位置和入口焦点。

使用球形地球和平行日照，太阳高度角为日面中心相对几何地平线的高度。实际日出、日落还受到折射、太阳视半径和地形影响。

## 实现与验收

1. 初始化静态应用和共享状态，锁定依赖及离线地图来源。
2. 实现太阳位置、晨昏线、正午高度与节气求解，用独立星历验证数值。
3. 接通 2D 与时间控件、两条曲线和节气面板，再接入 3D 与 WebGL 降级。
4. 用生产构建运行浏览器测试，检查桌面、手机触控、两个视图与计算层的联动。

数值回归包括 2026 年香港天文台 12 个中气样本，验收阈值为 2 分钟，以及 JPL Horizons 9 个无折射太阳高度角样本，验收阈值为 0.1°。JPL 样本使用目标 10、地表地理坐标、海拔 0 km、输出项 4，地点为北京、悉尼和特罗姆瑟。几何及时间测试另覆盖晨昏线上的零高度角、昼夜半球、四个节气的直射点纬度、闰日、极点、跨日界线、当地缺失日期和 23／25 小时日。

## 自然地理专题扩展

专题由首页 URL 片段定位。日照状态在同一浏览器会话内跨专题保留，切出时暂停。洋流、大气和气候的时间轴分别选择气候态月份，造山时间轴选择模型年代。专题代码与数据按需加载，成功加载的数据在本页面缓存，失败时可重试。网站仍可部署到静态 HTTP 服务的子目录。

现代地图使用等经纬度投影，数据网格按经度从西到东、纬度从北到南排列，经度归一至 [−180°, 180°)。气候剖面取同一网格的最近单元。造山地球用正射投影截取可见半球。Canvas 底图、栅格和箭头按尺寸或数据变化重绘，洋流粒子动画单独绘制，可关闭并遵循系统的减少动态效果设置。

### 数据生成与验证

按需重跑 `python scripts/prepare_topics.py`，可在命令后指定 `ocean`、`atmosphere`、`mountains` 或 `climate`。预处理依赖 Python、NumPy、SciPy、netCDF4、Requests 和 Shapely。原始文件默认缓存到系统临时目录的 `geography-topic-sources`，可用 `--cache` 指定。站点只分发 `public/data/` 中的派生数据，清单记录源 URL、原始快照和输出文件的 SHA-256。底图使用 [Natural Earth](https://www.naturalearthdata.com/about/terms-of-use/)。

网格为小端 IEEE Float32，缺测值为 NaN。洋流按「月份、U/V/SST、纬度、经度」排列。大气风场按「月份、850/200 hPa、U/V、纬度、经度」排列，后接「月份、经向风/ω、气压、纬度」剖面。气候按「月份、气温/降水、纬度、经度」排列，最后追加地形平面。造山使用 JSON 记录离散年代、重建线和参考点。各专题加载时校验数据长度或年代列表。

实施顺序及验收条件见[专题实施计划](topic-implementation-plan.md)。
